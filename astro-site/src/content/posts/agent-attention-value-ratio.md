> **我的核心观点是：尽可能少地占用人类注意力，但尽可能地创造价值。**

## 我的出发点

我认为，在和智能体进行人机交互时，交互过程中的每一个部分，都应该放在它消耗了多少人类注意力这个尺度上进行评判。

一条消息、一条通知、一个问题、一个设置、一个面板元素和一段文档，每一项都需要消耗用户的注意力。对我来说，任何一项交互内容都必须提供**大于其所消耗注意力的价值**。如果做不到这一点，它就应该被重新设计，或者直接移除。

我并不是单纯追求“少交互”。我真正关心的是，智能体是否把人的注意力当作一种稀缺、昂贵且不可逆的资源来管理。只有那些值得打断、值得阅读、值得决策的内容，才应该抵达用户面前。

## 我理解的设计哲学演变

在我看来，智能体的设计重点，正在从“如何让用户更方便地操作系统”，逐渐转向“如何让系统在不打扰用户的情况下创造结果”。我把这个演变理解为以下几个阶段：

1. **工具哲学：等待用户操作**
   - 系统提供功能，用户主动发起、配置和推进。
   - 这一阶段主要关注功能是否完整、入口是否清晰。

2. **对话哲学：响应用户表达**
   - 用户通过自然语言提出需求，智能体回答问题或执行指令。
   - 这一阶段主要关注回答质量与交互流畅度。

3. **代理哲学：替用户完成任务**
   - 智能体开始规划、调用工具、处理异常并交付结果。
   - 评价重点也随之从“回答得好不好”变为“任务完成得好不好”。

4. **注意力哲学：只在必要时占用用户**
   - 我希望智能体默认自主推进，把常规决策、信息筛选和过程执行留给自己。
   - 只有在遇到高风险、不可逆、真正需要用户偏好的决策，或无法可靠判断的关键分叉时，才请求人类介入。
   - 评价重点因此变成：**每一次人机交互是否值得消耗人的注意力。**

5. **价值创造哲学：用最小注意力换取最大复利**
   - 我期待智能体不只完成一次任务，还能沉淀可复用的记忆、技能、判断规则、自动化流程和环境模型。
   - 在我看来，最理想的智能体不是“更会聊天的助手”，而是一个能够持续减少未来负担、持续扩大用户能力边界的系统。

## 我所理解的注意力预算：所有交互都有成本

我倾向于把用户的注意力看作智能体的一项有限预算。每次交互发生前，都应该进行一次隐含的成本—价值判断：

> **交互价值 / 注意力成本 > 1，才值得发生。**

我所说的“注意力成本”，不只包括阅读时间，还包括：

- 从当前工作切换到智能体的打断成本；
- 理解上下文和判断选项的认知成本；
- 做出选择、确认或授权的决策成本；
- 处理通知、设置和面板带来的维护成本；
- 对智能体输出进行复核、纠错和善后所需的成本；
- 因频繁打扰而形成的警觉、疲劳和信任损耗。

因此，我认为一条看似简短的“请确认”，也可能比一段长文消耗更多注意力。它不仅把决策责任重新推回给用户，也打断了用户当前的心理上下文。

## 我会如何审查交互元素的价值

对于任何准备呈现给用户的内容，我会尝试追问四个问题：

1. **这是用户现在必须知道的吗？**
2. **这是只有用户才能决定的吗？**
3. **如果延迟到汇总时再呈现，会造成损失吗？**
4. **它创造的价值，是否大于打断、阅读、理解和决策的总成本？**

基于这四个问题，我对不同交互元素的理解是：

- **消息**：不应该因为“有进展”就汇报，只有会改变用户判断或行动的进展才值得汇报。
- **通知**：不应该因为“发生了事件”就提醒，只有需要及时干预或存在时间窗口的事件才值得打扰。
- **问题**：不应该一遇到不确定性就提问，智能体应先自行探索、缩小选项，并在真正的决策分叉处提出最小问题。
- **设置**：不应该把系统能力全部暴露给用户，而应优先自动推断；只有稳定、重要且用户确实需要控制的变量，才值得提供设置。
- **面板元素**：不应该展示所有状态，而应展示与当前目标、风险和下一步行动相关的状态。
- **文档**：不应该只是记录系统做过什么，而应帮助用户在需要时快速理解、复核、接管或迁移。

## 我对智能体行为的具体要求

### 1. 默认自主推进，而不是默认请求确认

我希望智能体把“我可以继续做什么”作为默认问题，把“我必须让用户决定什么”作为例外问题。

对于低风险、可逆、符合既有偏好的事项，我认为智能体应该直接执行；对于高风险、不可逆、影响范围大的事项，才请求授权。

### 2. 提问必须经过压缩

当智能体确实必须提问时，我希望它在提问之前先完成这些工作：

- 自己能查的资料先查完；
- 能通过试验验证的路径先验证；
- 将多个相关问题合并为一个高信息密度的问题；
- 提供推荐选项、理由和默认路径；
- 明确如果用户不回复，智能体将采取什么安全的默认行动。

在我看来，好的问题不是把不确定性原样转交给人，而是先把复杂的不确定性压缩成一个用户值得回答的决策。

### 3. 汇报结果，而不是倾倒过程

我不认为过程日志、工具调用和中间推理应该默认推送给用户。用户真正需要的是：

- 已完成什么；
- 产生了什么价值；
- 有哪些重要风险或偏差；
- 还需要用户做什么；
- 如果不需要用户做什么，就安静地结束。

### 4. 用可审计性换取低打扰

我认为，减少打扰不等于黑箱运行。智能体应该在后台保留可检索的行动记录、证据、决策依据、版本和回滚路径，让用户可以在需要时复盘，而不是被迫实时观看全过程。

因此，我理想中的交互结构是：

> **前台低打扰，后台高可追溯；平时安静，出问题可解释。**

### 5. 把一次性劳动转化为长期资产

在我看来，智能体创造的最高价值，不只是完成当前任务，而是把任务中的规律沉淀为：

- 用户偏好；
- 可复用技能；
- 经过验证的工作流；
- 对环境和系统的结构化理解；
- 失败教训与安全边界；
- 可持续更新的自动化程序。

如果每次任务都从零开始，我认为智能体只是一个更快的临时工；如果每次任务都会减少未来的交互成本，它才开始成为真正的复利资产。

## 我认为需要保持的平衡：少打扰不等于少沟通

我不希望“尽可能少地占用注意力”被误解为“尽可能少说话”或“完全不向用户汇报”。如果智能体过度沉默，可能会造成：

- 用户不知道系统是否仍在工作；
- 用户无法及时发现方向性错误；
- 用户失去对重要决策的控制感；
- 失败发生后才暴露，导致更高的纠错成本。

所以，我追求的不是交互次数最少，而是**无效交互最少、有效交互密度最高**。

我认为，智能体应该在以下时机主动出现：

- 目标或约束发生了实质变化；
- 即将进行高风险或不可逆操作；
- 需要用户独有的偏好、授权或现实世界信息；
- 已经获得了值得用户关注的成果；
- 继续自主行动的预期价值低于请求帮助的价值。

## 我认为可以形成的评估指标

未来评价一个智能体时，我不认为只看任务成功率就够了，还应该关注：

- **单位注意力价值**：每分钟用户注意力带来的任务价值；
- **有效交互率**：真正改变结果的消息/问题占全部交互的比例；
- **打断准确率**：需要及时介入的事项是否被打扰，非必要事项是否被静默处理；
- **自主完成率**：无需用户介入即可完成的任务比例；
- **问题压缩率**：智能体替用户消除的不确定性占原始不确定性的比例；
- **交互负担趋势**：随着记忆、技能和偏好积累，完成同类任务所需的注意力是否下降；
- **价值复利率**：一次任务沉淀的资产对后续任务产生了多少增益；
- **信任校准度**：系统在高置信度时是否果断，在低置信度时是否及时暴露不确定性。

## 我看到的与近期 Agent 研究的连接

我认为，这一设计哲学与几个正在形成的方向相互呼应：

- **MemCompiler 的“编译而非注入”**：它提醒我，不要把所有记忆一次性塞进上下文，而应根据当前状态按需编译。对应到人机交互，我也不应该把所有信息一次性推给人，而应按需呈现。
- **RAX 的探索→程序**：它提醒我，不要让人类持续监督每一步，而应通过探索把高层决策沉淀成可自动运行的程序，逐步减少人的在环频率。
- **EmbodiSkill 的定向进化**：它提醒我，不要因为一次执行失败就全面改写技能，而应区分知识缺陷与执行失误，进行最小范围修订，避免把纠错成本再次转嫁给人。
- **前后端分离与安全护栏**：它让我看到，减少人类注意力占用的前提，不是放弃控制，而是把底层安全、边界检查和可回滚机制内置到系统中。

## 我现阶段的工作假设

> **一个优秀的智能体，应当让用户感觉“我几乎没有被打扰，但事情确实在持续变好”。**

进一步说，我希望：

- 用户不必成为智能体的实时调度器；
- 用户不必被迫重复提供已经表达过的信息；
- 用户不必为系统本可以自行解决的不确定性做决策；
- 用户可以把注意力集中在只有人才能完成的判断、创造和关系上；
- 智能体的长期目标，是让用户未来需要投入的注意力越来越少，同时让可获得的成果越来越多。

这可以作为我评估智能体产品、工作流和 Agent OS 设计的长期标准：

> **每增加一个交互元素，我都应该追问：它为用户创造的价值，是否超过了它从用户那里拿走的注意力？如果不能，就删掉它。**
