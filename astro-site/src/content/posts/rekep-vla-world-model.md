## 从论文方法继续追问

上篇已经说明，ReKep 把自然语言任务转换成分阶段的关系关键点约束，再由优化器求解机器人末端轨迹。它提供的是一种显式任务表示，并不是完整的机器人基础模型。

但把 ReKep 放回当前 Physical AI 技术版图，还需要回答两个问题：

1. 如果 VLA 已经可以从视觉和语言直接生成动作，为什么还需要 ReKep？
2. 如果世界模型能够预测未来，ReKep 的闭环重规划算不算世界建模？

本篇不再重复论文的完整方法，而是比较三者的系统职责、能力边界和组合方式。

## 核心结论

ReKep、VLA 和世界模型解决的不是同一个问题：

- **ReKep** 描述“任务必须满足什么空间关系”。
- **VLA** 决定“机器人下一步应该怎么动”。
- **世界模型** 预测“执行这个动作后，世界会变成什么样”。

因此，ReKep 不是早期版本的 VLA，也不是轻量版世界模型。它更接近一种**可执行、可优化、可检查的任务约束表示**。三者既可以分别形成机器人操作方案，也可以组合成更完整的“理解—规划—预测—执行”闭环。

## 从“插入插头”理解三者

假设任务是“把插头插入插座”。

### ReKep 的表达

ReKep 会把任务转换成一组分阶段的关系约束：

1. 抓取阶段：末端执行器接近插头的抓取关键点。
2. 对准阶段：插头中心与插孔中心重合，插头轴线与插孔轴线平行。
3. 插入阶段：在保持轴线对准的同时，沿插孔方向逐步接近。

这里描述的是**结果和过程需要满足的条件**，而不是直接给出每个关节如何运动。

### VLA 的表达

VLA 接收相机画面、语言指令和机器人自身状态，直接输出：

- 末端位置和姿态增量；
- 关节动作；
- 夹爪开合指令；
- 或未来一小段连续动作。

它从训练数据中学习“在类似场景下应该怎样行动”，很多几何和操作经验隐含在模型参数中。

### 世界模型的表达

世界模型接收当前状态与候选动作，预测：

- 插头会不会对准插孔；
- 是否会与插座面板碰撞；
- 插入后可能到达的位置；
- 未来若干帧图像、机器人状态或接触状态。

它提供的是**动作后果预测**。规划器还需要根据任务目标判断哪种预测结果更好。

## 三者的系统定位

| 体系 | 回答的问题 | 典型输入 | 典型输出 | 动作生成方式 |
|---|---|---|---|---|
| ReKep | 什么关系必须成立？ | 语言、RGB-D、3D 关键点 | 子目标约束、路径约束、数值代价 | 优化器根据约束求解 |
| VLA | 当前应该执行什么动作？ | 图像、语言、机器人状态 | 单步动作或动作块 | 神经网络策略直接生成 |
| 世界模型 | 执行动作后会发生什么？ | 当前状态、历史、候选动作 | 未来状态、视频或潜变量 | 本身通常不执行，由规划器使用预测结果 |

更抽象地说：

```text
ReKep：目标与约束
VLA：策略与动作
世界模型：环境变化与动作后果
```

## ReKep 与 VLA：显式约束和学习型策略

前篇介绍的 ReKep 链路可以压缩为：

```text
自然语言指令 + RGB-D 图像
        ↓
关键点与 VLM 生成分阶段约束
        ↓
分层约束优化器求解末端执行器位姿与轨迹
        ↓
视觉跟踪关键点并闭环重新规划
```

大模型生成的是“任务应该满足什么关系”，连续机器人动作仍由约束优化器求解。

VLA 的典型形式则是：

\[
a_{t:t+H}=\pi(o_t,l,q_t)
\]

其中：

- \(o_t\) 是视觉观察；
- \(l\) 是语言指令；
- \(q_t\) 是机器人关节、末端或其他自身状态；
- \(a_{t:t+H}\) 是当前动作或未来一段动作；
- \(\pi\) 是学习得到的策略模型。

[OpenVLA](https://arxiv.org/abs/2406.09246)、[π₀](https://arxiv.org/abs/2410.24164) 和 [π₀.₅](https://arxiv.org/abs/2504.16054) 都属于这一方向。它们通过大量机器人示范和视觉语言数据学习从观察与指令到动作的映射。

二者的根本差异是：

- ReKep 把任务要求**显式写成约束**，再进行在线求解。
- VLA 把操作经验**隐式学习进模型参数**，推理时直接产生动作。

## ReKep 与世界模型：事后重规划和事前预测

世界模型通常学习状态转移或观察变化：

\[
\hat{s}_{t+1:t+H}=W(s_t,a_{t:t+H})
\]

其中，\(W\) 根据当前状态和候选动作预测未来状态。预测结果可能是结构化状态、潜变量，也可能是未来视频。

原始 ReKep 没有学习这样的环境动力学模型。正如上篇所述，它能够在物体被移动后重新规划，是因为系统持续跟踪关键点，并根据新的关键点位置再次求解约束，而不是先在模型内部模拟动作后果。

因此要区分两种“适应”：

- **ReKep 的适应**：看见环境变化后，重新感知并重新优化。
- **世界模型的适应**：执行之前，预测不同动作可能导致的未来。

[Cosmos-Predict1](https://research.nvidia.com/labs/dir/cosmos1/)所代表的世界基础模型可以通过动作、轨迹或指令进行条件化，生成未来视频或预测未来世界状态。这类模型可用于数据生成、策略训练和在线规划，但“生成逼真视频”并不自动等于拥有可靠的机器人动力学模型。

## ReKep、VLA 与世界模型如何组合

下面是一种现代混合架构。它不是原始 ReKep 论文的实现，而是三种能力的组合方式：

```text
语言任务 + 当前场景
        ├→ VLM / 推理模型：任务理解与阶段分解
        │          ↓
        │       ReKep：定义子目标、路径与安全约束 ─┐
        │                                           │
        └→ VLA：提出候选动作或技能                  │
                   ↓                                │
              世界模型：预测候选动作结果 ──────────┤
                                                   ↓
                                           约束评价器
                                                   ↓
                                      轨迹规划器 / MPC
                                                   ↓
                                         机器人控制器执行
                                                   ↓
                                      视觉、关节、力觉反馈
                                                   └→ 下一轮规划
```

在这个架构中：

1. 推理模型把长任务拆成可以执行的阶段。
2. ReKep 把阶段目标转换成可计算的几何条件和安全条件。
3. VLA 利用从数据中学到的动作先验，提出一个或多个候选动作。
4. 世界模型预测这些候选动作可能导致的未来。
5. ReKep 对预测结果进行评分或可行性检查。
6. 规划器与控制器完成碰撞检查、轨迹生成和实时执行。
7. 真实反馈进入下一轮规划，避免模型预测误差持续积累。

若以数学形式概括，可以写成：

\[
a^*=\arg\min_{a \in \mathcal{A}_{\text{VLA}}}
C_{\text{ReKep}}\bigl(W(s,a)\bigr)
\]

含义是：VLA 提出候选动作集合，世界模型预测每个动作的后果，ReKep 判断哪种后果最符合任务约束。

## 当前趋势：VLA 与世界模型正在融合

传统上，VLA 和世界模型的训练目标不同：

- VLA 重点学习从观察到动作的策略映射。
- 世界模型重点学习从状态和动作到未来状态的前向动力学。

当前模型正在同时学习语言、图像、视频、状态和动作，边界开始变得模糊。例如 [Cosmos 3](https://research.nvidia.com/labs/cosmos-lab/cosmos3/)把以下能力放进统一的多模态世界模型：

- **Policy Mode**：从观察和目标直接生成动作。
- **Forward Dynamics**：根据状态与动作预测未来。
- **Inverse Dynamics**：根据状态变化反推动作。

由视频或世界模型骨干进一步训练、既能理解世界变化又能输出动作的模型，也开始被称为 **World-Action Model，WAM**。不过，即使这些能力被装进同一个大模型，工程上仍然需要区分：

```text
任务是否正确：由目标和约束判断
动作是否有效：由策略提出
后果是否可接受：由世界预测和风险评价判断
运动是否安全：由规划器与控制器保证
```

模型能力融合，不意味着系统责任可以混在一起。

## 如何选择

| 场景 | 更适合的主体方案 | 原因 |
|---|---|---|
| 目标关系清晰、数据较少、需要解释和审计 | ReKep + 轨迹优化 | 约束显式，任务变化后可重新求解 |
| 开放场景、物体差异大、操作难以手写规则 | VLA | 可从跨任务示范中学习动作先验 |
| 需要执行前预演、长时序规划或失败恢复 | 世界模型 + 规划器 | 可以比较候选动作的未来后果 |
| 精密插入、装配、力控、工业安全 | ReKep/任务约束 + 专用技能 + 确定性控制器 | 需要明确边界、实时控制和失败判据 |
| 通用服务机器人或复杂双臂操作 | VLA + 约束 + 世界模型 + 控制器 | 同时需要泛化、预测、验证与可靠执行 |

对于精密机械臂系统，更稳妥的责任边界是：

> VLA 负责理解场景并提出动作，世界模型负责预测动作后果，ReKep 负责定义成功条件，运动规划器和控制器负责保证动作可执行。

特别是插入、装配和接触任务，毫米级对齐、碰撞边界、速度限制、力控、到位检测和超时处理不宜只依赖 VLA 的隐式策略。

## 专有名词说明

| 专有名词 | 中文说明 | 在机器人系统中的作用 |
|---|---|---|
| Action | 动作 | 机器人在一个控制周期内执行的命令，例如关节位置、速度、力矩或末端位姿增量。 |
| Action Chunk | 动作块 | 一次输出未来多个时间步的动作，降低大模型逐步推理带来的延迟，并提高动作连续性。 |
| Affordance | 可供性、功能可操作性 | 描述物体或局部区域能支持什么行为，例如杯柄适合抓取、按钮适合按压。 |
| Closed-loop Replanning | 闭环重新规划 | 执行过程中持续读取反馈；场景变化或约束被破坏时，重新计算后续动作。 |
| Constraint | 约束 | 对目标状态或运动过程的限制，例如距离小于阈值、轴线保持平行、不得发生碰撞。 |
| Diffusion Policy | 扩散策略 | 使用扩散生成模型产生连续动作分布的策略，擅长表达多种可能动作和复杂连续轨迹。 |
| End Effector | 末端执行器 | 机器人与环境直接交互的末端部件，例如夹爪、吸盘、焊枪或灵巧手。 |
| Forward Dynamics | 前向动力学模型 | 根据当前状态和动作预测未来状态，回答“这样做之后会发生什么”。 |
| Inverse Dynamics | 逆动力学/动作反推 | 根据希望实现的状态变化推导所需动作；在学习模型语境中也常指从观察转移反推动作。 |
| Keypoint | 关键点 | 图像、点云或物体上的语义位置，例如杯口中心、把手末端、插头尖端。 |
| LLM | 大语言模型 | 处理语言理解、任务分解、代码或约束生成；本身通常不直接感知机器人图像。 |
| MPC | 模型预测控制 | 在有限预测窗口内反复优化动作；每次只执行一部分，再根据新状态重新求解。 |
| Policy | 策略 | 从当前观察或状态映射到动作的函数，常写成 \(a=\pi(s)\)。 |
| Proprioception | 本体感知 | 机器人对自身状态的测量，例如关节角、关节速度、末端位姿、电流和力矩。 |
| ReKep | 关系关键点约束 | 用多个 3D 关键点之间的空间和时间关系表达操作任务，并将其转换为可优化的数值代价。 |
| Robot Foundation Model | 机器人基础模型 | 在多任务、多场景或多机器人数据上预训练，并可继续适配具体机器人和任务的大模型。 |
| SE(3) | 三维刚体位姿空间 | 同时表示三维位置和三维旋转；机器人末端目标位姿通常属于 SE(3)。 |
| State | 状态 | 对当前世界和机器人的描述，例如物体位姿、关节状态、接触状态或模型潜变量。 |
| TAMP | 任务与运动规划 | 同时处理“先做什么”的离散任务规划和“怎样移动”的连续几何运动规划。 |
| Trajectory Optimization | 轨迹优化 | 将目标、动力学和约束写成优化问题，求解一段连续可行的机器人轨迹。 |
| VLA | 视觉—语言—动作模型 | 联合处理视觉、语言和机器人状态，并直接生成动作或动作块的学习型策略。 |
| VLM | 视觉语言模型 | 联合理解图像和文本，可识别物体、理解空间关系并生成语言或结构化结果。 |
| World Model | 世界模型 | 学习环境如何随时间和动作变化，用于未来预测、规划、策略训练或数据生成。 |
| World Foundation Model | 世界基础模型 | 在大规模视频或多模态数据上预训练，再面向机器人、自动驾驶等场景进行适配的通用世界模型。 |
| WAM | 世界—动作模型 | 同时建模世界变化和机器人动作的模型，试图把视频预测、动作理解与策略生成结合起来。 |

## 最终判断

ReKep 的价值不在于替代 VLA 或世界模型，而在于提供一个位于大模型推理和机器人执行之间的**显式任务契约**：

- 对上承接自然语言、视觉理解和任务分解；
- 对中提供可计算的目标、路径和安全约束；
- 对下连接轨迹优化、技能执行和实时控制器；
- 对执行结果提供可验证的成功判据。

因此，在现代 Physical AI 架构中，可以把三者理解为：

```text
VLA 提供动作泛化能力
世界模型提供未来预测能力
ReKep 提供约束表达与结果验证能力
```

真正可靠的机器人系统通常不会只选择其中一个，而是让学习模型负责泛化，让显式约束负责边界，让确定性控制负责落地。
